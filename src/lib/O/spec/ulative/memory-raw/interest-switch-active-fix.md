Two bugs the user hit switching Interest caps (`.isx-cap`), **one root**: the session `%active` Waft flag was only ever set by `+Now` / `e_Lies_ghost_pick`, **never by the strip-foreground path**. (1) the dock doesn't follow the switch; (2) the next heartbeat whisks focus back to `wafts[0]` (= Peeroleum) ALWAYS, even off a Trail cursored elsewhere — because the per-tick acquire resolver (`Lies.svelte` ~832) is `wafts.find(.sc.active) ?? cur_waft-match ?? wafts[0]`, and a **stale `.sc.active` on Peeroleum wins line 1 over your real cursor on line 2**. ("Pmirrors presence is correct" = `ActiveInterest` is set Lang-side eagerly, so the graft follows; only the Lies-side dock didn't.)

**FIX — THREE edits (typeclean per `npm run check`, browser-UNVERIFIED, uncommitted):**
- `e_Lies_foreground_waft` (`Lies.svelte`): clears all `.sc.active` + sets it on the foregrounded Waft + `bump_version()`, THEN lands the cursor (mirrors `e_Lies_now_Waft`). So the resolver desires the foregrounded Waft — no stale drag-back.
- `e_Lang_foreground` (`Lang.svelte`): condition widened `kind==='Trail'` → `kind==='Trail' || (kind==='Aside' && waft)`. **Aside cap clicks were routed to the in-place `else` branch** (`interest_foreground`, Lang-side only: sets ActiveInterest + arms LE → Pmirrors follow, but NO Lies cursor-land → dock stuck). Now Aside lands the cursor like a Trail. SAFE: `Lang_set_interest` (`LiesHold` ~508-509) is already **stance-aware** (binds the Aside row, not a stray Trail — that flicker was pre-fixed).
- **`Waft_cursor_first` (`LiesCurse.svelte` ~454) — THE actual blocker, found on 2nd report ("only difference is Easy has the Points").** The first two edits were INERT alone: the `%active` claim desires the Aside, but the cursor had nothing to land ON, and the **dock follows the cursor**, not the desired Waft. `Waft_cursor_first` only landed on Whats-with-direct-Points (`Lies_what_has_direct_points`) or **Docs that are DIRECT children of the Waft** — an Aside scratch dump has neither (no Points; its Docs ride under the moment-Whats via `moment.i({Doc})`). So `first===undefined` → `return`, no `Lies_want`, cursor never enters. FIX = a **`docful` fallback**: when no Points-What exists, land on the first What that merely carries a `%Doc`. `Waft_src_doc` (`LiesHold` ~1532) already resolves a Doc-bearing What's dock. Normal givers (Points present) are byte-identical.

- **`Lies_focus_waft` shared selector (`Lies.svelte`) — THE trickle-revert fix (4th edit, found from a live snap).** Edits 1–3 made the dock ARRIVE on click but it reverted every trickle. Snap showed why: `req:acquire` is a **ONE-SHOT boot seed** (`desire.finish(acquire)`), so `req:desire`'s `Waft` lock froze on the boot Waft (Easy) and never re-picked. `req_timemachine` (runs every tick) read that **frozen desire lock** and re-landed the cursor on it → `Waft_cursor_first(Easy)` (cursor now in Aside ≠ Easy, ≠ undefined → no no-op) fired a `cold` want back into Easy → `req_understanding`/`ActiveInterest` flipped back. TWO un-shared owners of "which Waft" (the user's "share the mutexity"). FIX = extracted `Lies_focus_waft(w)` = `.sc.active ?? cursor's-waft ?? first-non-boring`; BOTH the acquire seed AND `req_timemachine` now select through it, so `.sc.active` (set by foreground/+Now/ghost_pick) is the single truth. `req_timemachine` also re-points the snap-visible desire lock to the focus waft so the snap stays honest. The one-shot acquire is now just a boot seed.
