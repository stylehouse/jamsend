A Story shares a set of EntropyArrest Entcases (acknowledged-noise spayers) with other Stories by **referencing another Waft** instead of inlining them.

- **The shared Waft:** `Waft:Trope/Lies/NormalEntropy` (`wormhole/Trope/Lies/NormalEntropy/toc.snap`) holds the common Entcases — originally 6 (Ting waft via `Languinio/Interest`, Ting cursor, Compile time, w self-round, req:wants, Change secs) lifted from LakeSurfer; **+1 (2026-06-24): `Lies_Waft:Ting` at `w:Lies / Waft,takes` → `re:Waft:Ting/{INT}-{INT}-{INT}/{INT}.takes,tol:any`** promoted up from LakeTiles (a distinct Ting-waft line from the Languinio/Interest one). LakeTiles now = profile + own LakeTiles.g-specific (`theCompiledStuff_say-at`, `Ting_Point-last`); LakeNets has its own `want.kind`.
- **The reference:** `The/EntropyProfile,Wref:Trope/Lies/NormalEntropy`. **`Wref:` is the greppable cross-Waft-link token** — keep it consistent; a future link registry / ACID pass greps for it.
- **`Trope/**` = composite, reusable bits of Story** (fragments, not whole canonical stories). The home for shared representation. Sibling `Trope/Lang/NormalEntropy` later (noise sorts by whose state it is).
- **CANONICAL (not stealth) — opened as a real Lies roster Waft:** Story (`Story.svelte` toc-load) does NOT deWaft itself anymore. It fires `i_elvisto('Lies/Lies','Lies_open_Waft',{path:ref})` ONCE (`p.c.opened`, runtime flag) and DOESN'T block. Lies `LiesStore_read_waft`→`deWaft` places `Waft:ref` under `w:Lies` as a live C tree (EntropyArrest→Entcase) + `watch_c→Lies_waft_save` **autosaves on edit**. The old `top.c.entropy_profiles` map is DELETED.
- **TOPOLOGY GOTCHA (the hang bug, fixed):** elvis does NOT aim at the outside Lies — it aims at the **NEAREST**, which during a Story Run is the **inner Run Lies** (created on the Run House, beside Waftily; `Editron.svelte:47`, `LiesWaft.svelte:493-497`), NOT `top_House()`'s Lies. My first cut opened into the inner Lies but READ from `top_House()`'s Lies → gate never cleared → blocking `return w.i({see})` hung the whole Story before its Preps (no action buttons, no Langui; Lies-think/Wormhole-rw_op storm). Fix = fire-once + non-blocking + a **scan helper**.
- **`entropy_profile_waft(ref)` (Hovercraft):** the single source of truth for finding a profile's roster Waft — scans EVERY house (`top_House().all_House` = [self,...descendants]) for `A:Lies/w:Lies/Waft:ref`, so it finds the Waft wherever the open landed (inner or outside). Used by all 3 sites: Story skip-check, Hovercraft `entropy_rules` union, EntropyArrest UI `shared` derived. Consequence: profile lands in the inner Run Lies → reloads per run (NOT the cross-run cache the design wanted; correctness>caching for now). Type-clean except the usual undeclared-method-on-House baseline warning.
- **`%boring` = backstage Waft (the canonical-Waft-leaks-into-snap fix):** opening the profile into `w:Lies` made it leak into the step snap (whole EntropyArrest tree + its load `Good` + a Lang `Interest:Trail,lens:NaviCado` + `see:N Wafts` count). Fix = a single master flag `boring` (the user's "Waft,dontSnap,boring"), declared **self-describingly in the Waft's OWN toc.snap root** (`Waft:Trope/Lies/NormalEntropy,boring,dontSnap`). Honored at the surfaces that surface Wafts: (1) **snap_H** `Story.svelte:~1019` `if (n.sc.boring||T.sc.boring){T.sc.more=[];T.sc.not=true;return}` fully hides node+subtree (vs dontSnap which only prunes subtree, keeps the line) — covers the Waft tree AND its Good. **GOTCHA (cost a round):** snap_H builds the snap TWICE — the normal `lines.push` path, AND when loopy/shared-C refs exist (e.g. `Languinio{loopy:2}`) a **rebuild pass** (`Story.svelte:~1078`) re-collects every D whose `snap_line` is set, skipping only `T.sc.not`. `story_process_node` stamps `snap_line` BEFORE the boring check, so just `return`-ing before `lines.push` is NOT enough — the rebuild re-adds it (line shows, subtree pruned). Must set `T.sc.not=true` so BOTH passes skip it. (2) **Lies placement** `Lies.svelte:~715` propagates `waft.sc.boring → good.sc.boring` (before watch_c, so no save fired); (3) **Waft count** `Lies.svelte:~615` filters boring; (4) **Lang roster** `Lang.svelte:~2017` `.filter(e=>!H.waft_is_boring(e.path))` so no Interest. `waft_is_boring(path)` (Hovercraft) = `!!entropy_profile_waft(path)?.sc.boring`. `entropy_profile_waft`'s `o({Waft:ref})` still matches (extra sc ignored) so entropy matching + the CRUD group still see it. NOT-yet-folded-in: GhostList's `dontSnapGhostList` Opt + Cluster's `dontSnap ??= 1` are the same backstage idea, candidates to unify under `boring`.
- **Two MORE leaks `boring` didn't cover (both fixed) — the profile *perturbed the test* even while hidden:** (a) **acquire-stealing:** `w:Lies/req:desire/req:acquire` (Lies.svelte:~828) holds until *a* Waft is present then locks `find(active)??cur_waft??first`; the profile opened early won the gate → dragged the whole editor focus (Spotlight/LE/Seem/Demonstrations/Pmirror/Interest off `What:itis`). Fix: `const wafts = w.o({Waft:1}).filter(wf=>!wf.sc.boring)` — backstage never acquired. (b) **child-order shift:** opening the profile during toc-load WAKES Lies before the Plan's Preps open Waftily, so `w:Lies`'s reqs (desire/git/wants) get created in a different order → the always-fresh `want=<ts>` lines mis-align and don't graft. Fix: **defer** the open (Story.svelte block already runs every drive tick, outside the `toc_loaded` guard) until `foreground_up` — a non-boring Waft is already in some Lies roster (`all_House` scan). Lesson: a Waft hidden from the snap can STILL change it, via the machinery that *reacts* to a new Waft (acquire, desire-wake, ordering) — hide it AND keep it from waking that machinery early.
- **BETTER HOME — aim the open at the OUTSIDE (Mundo) Lies, not the inner test Lies:** the test snap is rooted at `H:<Book>,Run`, so Mundo's `Lies,runner` sits OUTSIDE it — a profile loaded THERE never enters the test snap (no `boring`/acquire/order issue) AND caches across runs. The reason it went inner: `i_elvisto('Lies/Lies')`→`_find_house` returns the NEAREST `A:Lies` up-tree, and the Run House has its own. Fix: `H.top_House().i_elvisto('Lies/Lies', 'Lies_open_Waft', {path})` resolves from Mundo's vantage → lands on Mundo's Lies. Falls back to the nearest (inner) when Mundo has no Lies (plain editor), so the boring/defer/acquire-filter guards stay as the inner-case safety net. The `%Good` is fully standard (`e_Lies_open_Waft`→`LiesStore_good` `text/Waft` under `req:Store`); it's just `boring`-propagated so hidden from the snap. **Verify on a runner:** Mundo's `Lies,runner` must actually provision an opened Waft (it's Creduler-specialised); if not, it stays inner via fallback.

**Repoint DONE — all 5 Lake* `toc.snap` reference the profile:** LakeSurfer (6→profile-only), LakeTiles (profile + own `theCompiledStuff_say-at`), LakeNets (profile + own `wants_want`), LakeFlush + LakeSurprise (profile-only; had none). EntropyArrest lives in `The`, NOT in snapped step output → diges unchanged, no step re-record needed. Over-specific baked date (`Ting/2026-06-21/040014` in Ting_cursor) dropped via the generalized profile copy. Unverified by a run (:9091).

Header **open ⇗** (`open_profile`→`Lies_open_Waft`) just focuses the already-canonical roster Waft; its **autosave** (`Lies_waft_save`) persists any edit for every borrower — NO loose manual save. Typechecks clean (only pre-existing deL/entropy_suggest baseline errors).
