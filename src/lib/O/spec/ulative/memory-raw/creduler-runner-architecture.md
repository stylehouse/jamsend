**Gen-write via relay (landed):** the browser's File-System-Access `.go` write cost ~463ms (`createWritable`/`close` round-trips through the Wormhole rw_queue → `WormholeNav.write_file` → `DirectoryListing.getWriter`, real disk since dev uses a directory-picker handle, NOT OPFS). Now the editor SHIPS the compiled `.go` down its relay socket as a raw `{control:'gen_write', path, body}` frame; `relay.ts` (Node, has fs) validates the path (`gen/**.go` under `resolve('src/lib/gen')`, no traversal, ≤5MB) and `fs.writeFile`s it (~1ms) — Vite HMRs the file to BOTH origins (shared /app). `Lies_send_gen_write` (LiesLies) returns false if the ws isn't open → caller falls back to the local FSA `LiesStore_write`. When relayed there's no LiesStore_write req for req_Store phase-1 to hand off, so `e_Lies_compiled` stamps the Codebit's `write_finished=1` itself (optimistic settle — localhost Node write is reliable; failures show as relay `✗ gen_write`). NOTE: relay.ts is server code — the editor's dev server must restart to pick up the handler. Control frames aren't routed (handled in `handleControl`), so the 20KB body stays editor→its-own-relay.
