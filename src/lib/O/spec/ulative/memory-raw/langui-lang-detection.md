**Bug:** opening a `.md` dock kept the prior dock's stho grammar until `lang_override` was set by hand. `lang_for_path` detected markdown but it didn't land.

**Architecture (the trap):** Langui is **one EditorView, many EditorStates** swapped via `view.setState()`. `editorExtensions` (with `langCompartment.of(<initial lang>)`) is built ONCE in `build_editor` and **reused** for every fresh state — so a new dock's state starts on the FIRST dock's grammar. The reconfigure `$effect` (Langui.svelte ~645) is meant to correct it, but `last_applied_lang` went stale: the switch `$effect` swapped the compartment (to the baked first-dock lang) WITHOUT updating it, so `want === last_applied_lang` short-circuited and left the new doc on the wrong grammar. Plus an async race: `lang(want)` could resolve after a `setState` swap and dispatch onto the since-swapped state.

**EDITOR-DISPLAY FIX:**
- Switch `$effect`: after `view.setState(...)`, set `last_applied_lang` to the grammar the installed state actually carries — `baked_lang_name` (fresh) or `lang_override ?? lang_for_path(arriving)` (cached) — NOT `undefined` (re-applied every open, wasteful now a recompile rides it) and NOT the stale prior name (the original strand). Relies on Svelte-5 effect order: switch `$effect` (~507) created before reconfigure `$effect` (~645) → runs first in the flush.
- Reconfigure `$effect`: capture `my_view`+`my_path`; in the async `.then` bail if `view!==my_view || active_path!==my_path`, reverting optimistic `last_applied_lang` only `if(===want)`.

**COMPILE-PARSER FIX (the immutable-EditorState double-take).** The compile reads its parser off `dock.c.state.facet(language)` — a snapshot pushed via `Lang_i_elvis` on CM events; a reconfigure fires no event, so the new state never lands and the compile (reqonce, text-keyed) kept the stho Map (`md_parser:_LRParser`). FIX: reconfigure `$effect`, after the dispatch, fires `Lang_i_elvis(view,'Lang_compile',{})` — the same path Esc uses (`e_Lang_compile` = `Lang_dock_from_event` push + recompile) → fresh state to `dock.c.state` + recompile with the right parser → Map/Mapule rebuild → minimap unfurls. Gated to a real grammar change (via `baked_lang_name`) so no per-open double compile. Minor: switched-to .md briefly compiles stho first (harmless; gate-tightening `req_compile` to the RIGHT parser would remove it).

**Option B (deeper, NOT done):** `dock.c.state` snapshot lags any state change firing no event (this reconfigure; channel-compile one-round-lag band-aided at `Lang_compile_source_state`). Make `dock.c.view.state` the source of truth, snapshot only "compiled-against" where Map-offset consistency needs it. Touches every `dock.c.state` reader (LangPoint/LangGraft/fold/whatsthis/compile).

**Also:** bookmark syntax dump (`whatsthis_txt`) made UNCONDITIONAL (`Lang.svelte:~2179`, was `Opt/txtsyntaxdump`) — Ctrl+B always dumps the Lezer tree.

**Downstream lang+MiniMap flush (the "smaller thing", NOT Option B — UItime reactivity + a wake gap, orthogonal to the compile-source staleness):**
- **Dropdown render stale** (`Actions.svelte:26,28`): `value={a.sc.value}` / `disabled=…` didn't read `a.vers`, so the LangLang_tick particle bump never re-rendered the `<select>` (only `cls` threaded `a.vers`). Fixed: `value={(a.vers, a.sc.value) ?? ''}` (+ disabled). The lang-selector particle WAS tracking; only the render lagged. VERIFIED live (snap shows `lang_pick…value:markdown`).
- **Cache-key audit (the user's "unclear what our cache key is, for various things"):** the Navicade pipeline keys are — (1) `req:compile` reqonce = the literal constant `'firing'` (Lang.svelte:1921): parser-AND-text-blind, fires once per req lifetime; reset only on a TEXT change via the `compile_ready` gate (Lang.svelte:2216-2230 → delete firing/oncelers.firing/finished + `reqyoncile(languish)`). A LANGUAGE switch never resets it, so the dock's own req:compile NEVER re-fires on a parser change — only the `e_Lang_compile` band-aid (Esc path) recompiles, going straight to `Lang_compile_dock`, bypassing the req machine. (2) `req:instrumentation` sig = `path:content_dige:src_serial:LE.version:compile_v` — NOW parser-sensitive via the `compile_v` term I added; re-derived EACH TICK by the `req:workon` driver inside `w.do()` (Lang.svelte:820-871, 2158). (3) `MapReport.c.Map_dige` = digest of Map rows (correctly content-sensitive). (4) `Lang_build_mapules` = no cache, rebuilt every instrumentation run.
- **THE ACTUAL BUG (root cause): missing think poke.** `e_Lang_compile` (LangCompiling.svelte:156-175) recompiled the .md directly with the markdown parser (filled %Map with 25 regions, bumped %Compile version) but poked NO think — it's the ONLY compile path that doesn't (the channel/force_active path pokes one at Lang.svelte:1271; req:compile runs inside the driver tick). req:workon re-derives the instrumentation sig only inside its per-tick `w.do()`, and a language switch lands after the driver has quiesced. So the driver's last-derived sig stayed frozen at the STHO compile's compile_v (snap: `…:57:6`) while %Compile sat at a higher version with the full markdown Map → instrumentation never re-keyed → empty %Navicade + `MapReport,n_region=0` while %Map itself is correct. The snap is the proof: a frozen old compile_v in the sig + a full Map. FIX: `e_Lang_compile` pokes `this.i_elvisto(w, 'think')` after `Lang_compile` (LangCompiling.svelte tail). One think → driver re-derives sig (compile_v bumped) → instrumentation rebuilds Navicade/MapReport against the fresh Map. Also hardens Esc against a quiesced driver.
- The earlier `%Compile.version`-in-sig fix (Lang.svelte:~869) + `dock.bump_version()` in `Lang_build_mapules` (Lang.svelte:~1471) are NECESSARY (they make the sig parser-sensitive and let DocMinimap re-derive) but were NOT SUFFICIENT alone — without the think poke the sig is never re-evaluated. All three together close it.
